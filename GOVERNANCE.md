# Governance

Spaces uses a maintainer-led model.

- Maintainers set release scope, review contributions, and protect the security
  and privacy boundaries.
- Routine fixes can proceed through pull requests.
- Significant architecture, schema, provider, or governance changes should
  begin with a public issue or RFC.
- Decisions should be recorded in the relevant issue or pull request with the
  tradeoffs and rejected alternatives.
- Maintainers may decline changes that broaden data collection, weaken explicit
  approval, or make local behavior depend on a proprietary hosted service.

As the contributor base grows, maintainer and reviewer roles can be added based
on sustained, trustworthy contributions.
